## What changed
- `app/race/core.py`: `run_planner` turns a plan's trace into steps of best-so-far utility and regret after each
  search. Each candidate itinerary becomes available at the search that supplied its last ticket. The running
  maximum of the top-ranked utility is kept, so regret never rises and the last step equals what the planner
  returned.
- `app/api/race.py`, `POST /api/race`:
  - `mode=replay` serves the recordings for the demo trip. Unrecorded budgets for deterministic code planners are
    computed and cached; for `llm` they return 404, listing the recorded budgets.
  - `mode=live` runs fresh, with the `llm` planner on the baseline model inside the spend cap. It's limited to
    `RACE_LIVE_PER_HOUR` (default 3) per client, with HTTP 429 over the limit. The client is identified by
    `Fly-Client-IP`, else the socket address; `X-Forwarded-For` is ignored because a client can forge it.
- `data/race/recordings.json`: heuristic runs (real) and `llm` placeholder runs (labelled).
- `python -m app.race`: re-records. `--placeholder` uses the scripted stand-in; without it, `llm` uses the real
  baseline model and needs `OPENAI_API_KEY`.
- `app/api/deps.py`: `get_llm_factory` and `get_llm` moved out of `main.py` to avoid a circular import. `main.py`
  re-exports them, because the locked tests and `serve_fake.py` import them from there.

To replace the placeholder with real runs (makes real API calls, inside the spend cap):

```bash
cd backend && OPENAI_API_KEY=... uv run python -m app.race --planners llm
```

That's 4 conversations, one per budget (5/10/20/30).

## Open problems
- **The `llm` replay is a placeholder** until you run the command above. Nothing in the API hides that, but a UI
  that ignores `source` would. F18 must show it.
- **The rate limit lives in memory, per process.** It resets on restart and isn't shared between machines. That's
  fine for one Fly machine. Live races also spend from the same monthly LLM cap as everything else.
- **Replay covers only the demo trip at seed 0.** Other seeds compute the heuristic live and 404 for `llm`.
- **The race and the benchmark pass "best so far" slightly differently.** The race keeps a running maximum, the
  benchmark takes the planner's final #1. They agree whenever the top-ranked utility only rises, which is true in
  every run recorded so far.
